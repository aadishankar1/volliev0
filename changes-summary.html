Vollie Platform Changes Summary

This document outlines all changes made to the Vollie platform since the previous build, to help backend developers implement these features.

1. Landing Animation Fix

Landing Animation Behavior

The landing animation was modified to always display for non-logged-in users, removing the localStorage check that previously limited it to first-time visitors only.

Implementation Notes for Backend:

No backend changes required. This is a purely frontend change that modifies when the animation is displayed based on authentication state.

Code Changes:

// app/page.tsx
// Before:
useEffect(() => {
  const hasVisitedBefore = localStorage.getItem('hasVisitedBefore');
  if (!hasVisitedBefore) {
    setShowAnimation(true);
    localStorage.setItem('hasVisitedBefore', 'true');
  } else {
    router.push('/explore');
  }
}, [router]);

// After:
useEffect(() => {
  if (loading) return;
  
  if (user) {
    // If user is logged in, redirect to explore page
    router.push('/explore');
  } else {
    // Always show animation for non-logged-in users
    setShowAnimation(true);
  }
}, [user, loading, router]);

5. Backend Integration Requirements

Schema Updates

Initiative Schema

Add the following field to the Initiative schema:

  • isOpenInvite: Boolean - Indicates whether volunteers are automatically accepted

User Schema

Ensure the User schema has proper initialization for:

  • stats: Object containing user statistics
  • stats.achievements: Array of achievement objects
  • stats.dailyStreak: Number tracking consecutive days of activity
  • stats.lastVolunteerDate: String or null - Date of last volunteer activity

API Endpoint Updates

Initiative Endpoints

  • Update Create Initiative endpoint to accept and store the isOpenInvite field
  • Update Edit Initiative endpoint to accept and update the isOpenInvite field
  • Modify Initiative List endpoint to include the isOpenInvite field in responses

Volunteer Signup Process

  • Modify the volunteer signup logic to check the isOpenInvite flag
  • If isOpenInvite is true, automatically approve the volunteer without requiring organization approval
  • Send appropriate notifications based on whether the signup was auto-approved or requires manual approval

User Data Initialization

  • Ensure new users have properly initialized stats and achievements objects
  • Consider adding an endpoint to initialize missing user data if it doesn't exist
